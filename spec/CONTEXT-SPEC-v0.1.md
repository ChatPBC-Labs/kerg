# Kerg Context Spec — v0.1 (kerg/0.1)

Kerg is a **context layer** for robots. Manufacturers embed the `kerg` agent in the
robot's control stack at the factory. Owners then align their robot instantly by
editing two markdown files from their phone:

| Layer    | Authored by | Editable | Purpose |
|----------|-------------|----------|---------|
| `ROBOT.md` | Manufacturer | never | identity, capabilities, hard safety constitution |
| `SOUL.md`  | Owner        | phone push | personality, values, behavioral rules |
| `USER.md`  | Owner        | phone push | owner facts: name, household, accessibility, preferences |
| `SESSION.md`| Runtime     | ephemeral | optional scratch context, not pushed |

## File format

Plain Markdown with an optional YAML-subset front matter (flat `key: value` only;
comma-separated values act as lists):

```markdown
---
name: Nova
tone: calm, direct
---
# SOUL.md
You are Nova, our home robot.
- Never ignore the emergency stop.
```

### ROBOT.md front matter keys (manufacturer-reserved)

| Key | Meaning |
|-----|---------|
| `robot_id` | unique unit identifier |
| `model` | model name (e.g. `Optimus Gen-2`) |
| `manufacturer` | vendor name |
| `safety_locked` | `true` (default) enables override-detection heuristics |
| `editable_layers` | owner layers allowed to push (`soul,user`) |
| `deny_patterns` | comma-separated regexes rejected in owner docs |

## Precedence

`robot > soul > user > session`. All layers are merged into one prompt,
rendered by `GET /context` and served to the robot's behavior/LLM stack.

## Safety contract

Owner pushes are validated against `ROBOT.md` **before** acceptance:

1. Reserved front-matter keys in owner documents are rejected.
2. Override heuristics reject text attempting to disable safety
   ("override/ignore/bypass/disable ... safety/emergency/estop/limits").
3. Manufacturer `deny_patterns` are rejected.

Rejected pushes return HTTP 422 with reasons and are audited in the event log.

## Wire protocol (owners' phones -> robot)

- **Pairing:** `POST /pair {"code": "<6-digit>"}` -> `{"token": "<hex>"}`.
  The code is generated by the robot (shown on its screen / log) and is
  single-use, 5-minute TTL.
- **Push:** `POST /context/{soul|user}` with a signed body:
  ```json
  {"token": "...", "layer": "soul", "content": "# SOUL.md...",
   "ts": 1700000000, "nonce": "abc", "sig": "<hmac-sha256>"}
  ```
  `sig = HMAC-SHA256(token, layer + "|" + content + "|" + ts + "|" + nonce)` —
  reference implementations match byte-for-byte in Python (`kerg.core.signed`)
  and TypeScript (`kerg-mobile/src/lib/kergClient.ts`).
  Timestamps older than ±120s are rejected; version counters are per-layer
  and monotonic.
- **Events:** `GET /status`, `GET /context`; live updates over
  `ws://<robot>:7631` (`websockets` extra). Rejected: HTTP 401 (unpaired),
  403 (bad signature), 422 (safety), 400 (stale ts).

## Behaviour interface (manufacturers)

```python
from kerg.core.hooks import BehaviorHook

class MyHook(BehaviorHook):
    def on_context_update(self, snapshot):  # fires < 1s after push
        ...
```

ROS 2 deployments can use `kerg.ros2.adapter.Ros2BehaviorHook`, which
publishes the full merged stack on `/kerg/context`.
